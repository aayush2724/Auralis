> **Auralis** is an AI sales assistant for handling prospect objections. Every message is classified for **objection type**, **buyer persona** and **sentiment** using Google **Gemini** zero-shot classification, enriched with evidence retrieved from a **FAISS** knowledge base, and answered with a persona-specific, strategy-driven reply generated by Gemini inside a **LangGraph** pipeline. Conversations that need a human are escalated automatically. It ships with a React dashboard, JWT auth, PostgreSQL analytics and Prometheus metrics.

## 🏗️ Architecture

Auralis is a React single-page app talking to a single FastAPI service. The backend owns PostgreSQL (users, session facts, analytics events), Redis (A/B variant assignments) and an on-disk FAISS index. Each chat turn runs through a LangGraph `StateGraph`.

```
┌─────────────────────────────────────────────────────────────────────┐
│                          CLIENT  (Vercel)                           │
│                                                                     │
│   React 19 + TypeScript  ·  Vite  ·  Tailwind  ·  TanStack Query    │
│   Tabs: Sales Chat · Analytics · A/B Test · Knowledge Base          │
│   Chat over WebSocket with automatic HTTP fallback · JWT in browser │
└────────────────────────────────┬────────────────────────────────────┘
                                 │ HTTPS / WSS  (Bearer JWT)
┌────────────────────────────────▼────────────────────────────────────┐
│                       FASTAPI BACKEND  (Render)                     │
│                                                                     │
│   /auth/token   /chat   /ws/chat   /session/{id}                    │
│   /analytics/dashboard   /ab-test/results   /kb/ingest   /kb/stats  │
│   /health   /metrics (Prometheus)   /docs (Swagger)   /redoc        │
└───────┬───────────────────────────┬───────────────────────┬─────────┘
        │                           │                       │
┌───────▼──────────┐    ┌───────────▼─────────┐   ┌─────────▼──────────┐
│   PostgreSQL     │    │        Redis        │   │  FAISS  (on disk)  │
│  users           │    │  A/B variant per    │   │  vectorstore/      │
│  customer_       │    │  session_id         │   │  Google text-      │
│    sessions      │    │                     │   │  embedding-004     │
│  conversation_   │    │                     │   │                    │
│    events        │    │                     │   │                    │
└──────────────────┘    └─────────────────────┘   └────────────────────┘

                    LANGGRAPH PIPELINE  (one run per /chat turn)

  classify_node ──► retrieve_node ──► strategy_node ──► generate_node ──┬──► END
  Gemini zero-shot:  FAISS top-5       objection ×       Gemini, persona │
  objection+persona  + numbered        persona  →  one   system prompt + │ handoff
  (1 call) and       citations         of 6 strategy     strategy prompt │ trigger?
  sentiment (1 call) (skipped if no    prompt modules    (streamed)      ▼
                     index yet)                                    handoff_node ──► END
```

```mermaid
graph TD
    User([Browser]) <-->|REST + WebSocket · Bearer JWT| API[FastAPI]
    API --> AB{A/B variant}
    AB -->|STATIC| Static[Canned pitch, graph skipped]
    AB -->|ADAPTIVE| G[run_graph]

    subgraph LangGraph pipeline
        G --> C["classify_node<br/>objection + persona + sentiment<br/>(Gemini zero-shot)"]
        C --> R["retrieve_node<br/>FAISS top-5 + citations"]
        R --> S["strategy_node<br/>objection × persona → strategy"]
        S --> Gen["generate_node<br/>persona system prompt + strategy prompt → Gemini"]
        Gen -->|handoff trigger| H[handoff_node]
        Gen -->|otherwise| E([END])
        H --> E
    end

    API <--> PG[("PostgreSQL<br/>users · customer_sessions · conversation_events")]
    API <--> RD[("Redis<br/>A/B assignments")]
    R <--> FAISS[("FAISS index<br/>Google embeddings")]
```

### Pipeline in detail

| Node | What it does |
|---|---|
| `classify_node` | One structured Gemini call returns the objection label + confidence and the persona label + confidence. A second call classifies sentiment (`positive` / `neutral` / `negative`) and maps it to a tone instruction. Regex trigger phrases are extracted for explainability. |
| `retrieve_node` | Queries FAISS with `"<message> <objection> objection handling"`, takes the top 5 chunks, and formats numbered citations. If no index exists yet, the turn proceeds without retrieval. |
| `strategy_node` | Looks up `(objection, persona)` in a strategy map, e.g. `price × CEO → roi_business_case`, `trust × CTO → technical_proof`, falling back to the objection default. |
| `generate_node` | Builds a persona-specific system prompt (CEO, CTO, Developer, Product_Manager, Founder, Unknown) and a strategy prompt from one of six modules (`price`, `trust`, `timing`, `competitor`, `fit`, `buying_signal`), streams the reply from Gemini and appends the citations block. |
| `handoff_node` | Runs when a handoff trigger fires. The handoff message replaces the generated reply. |

## ✨ Features

<details open>
<summary><b>🧠 1. Classification & Generation</b></summary>

| Feature | Description | Tech |
|---|---|---|
| **Objection Classification** | Classifies each message into one of `price`, `trust`, `timing`, `competitor`, `fit`, `buying_signal`, `neutral`, with an LLM-reported confidence score | Gemini structured output |
| **Persona Detection** | Detects the buyer persona: `CEO`, `CTO`, `Developer`, `Product_Manager`, `Founder`; falls back to `Unknown` below 0.25 confidence | Gemini structured output |
| **Sentiment Analysis** | `positive` / `neutral` / `negative` per message, mapped to a tone instruction injected into the reply prompt | Gemini zero-shot |
| **Competitor Detection** | Regex dictionary of 14 CRM / sales tools (HubSpot, Salesforce, Pipedrive, Zoho, Gong, …) with an LLM fallback, used by the competitor strategy prompt | Regex + Gemini |
| **Strategy Routing** | `(objection × persona)` selects a named strategy; six prompt modules build the final instruction | LangGraph + dispatch table |
| **Role-Based Generation** | A distinct system prompt per persona reframes language, metrics and length for that buyer | Gemini |
| **Conversation Memory** | Extracts company name, tools mentioned, budget signals and objection history from each user turn and injects a context line into every prompt; facts persist across sessions | Regex + PostgreSQL |

</details>

<details>
<summary><b>📚 2. Knowledge Base & RAG</b></summary>

| Feature | Description | Tech |
|---|---|---|
| **Vector Retrieval** | Top-5 similarity search over ingested sales collateral | FAISS + Google `text-embedding-004` |
| **Multi-Format Ingestion** | `.pdf` (PyMuPDF), `.csv` (pandas) and `.md` files, chunked at ~512 tokens with 64-token overlap, via CLI or the Knowledge Base tab | LangChain text splitter |
| **Source Citations** | A numbered `[n] Title (file, chunk k)` block is appended to every reply that used retrieved chunks; the raw chunks are also returned in `retrieved_docs` | RAG pipeline |
| **Explainability** | Every response carries an `explanation` with the objection, persona, sentiment and strategy reasoning, trigger phrases, a confidence note and the handoff reason | `src/utils/explainability.py` |

</details>

<details>
<summary><b>⚙️ 3. Platform & Infrastructure</b></summary>

| Feature | Description | Tech |
|---|---|---|
| **Human Handoff** | Escalates when the user asks for a human, when objection confidence is below 0.40, or when negative sentiment exceeds 0.85 on a non-standard objection | Threshold rules |
| **A/B Testing** | `STATIC` (canned pitch, graph skipped) vs `ADAPTIVE` (full pipeline). The variant is stored per `session_id` in Redis and compared on `/ab-test/results`. **The 50/50 hash split is currently commented out and every session is assigned `ADAPTIVE`** | Redis |
| **Analytics Events** | One row per turn in `conversation_events` (objection, sentiment, persona, confidence, variant); aggregated into the dashboard | PostgreSQL |
| **JWT Authentication** | OAuth2 password grant at `/auth/token`, HS256 tokens, bcrypt password hashing, role guards on every protected route | FastAPI + python-jose + passlib |
| **Real-time Chat Transport** | `/ws/chat` WebSocket authenticated by `Authorization` header or `?token=`; the client falls back to `POST /chat` with retries if the socket fails | Starlette WebSocket |
| **Prometheus Metrics** | Request latency / count metrics at `/metrics`, plus an `auralis_objections_total` counter by label | prometheus-fastapi-instrumentator |
| **Structured Logging** | JSON logs for every HTTP request and every chat turn (labels, confidence, strategy, latency) | structlog |
| **OpenAPI Docs** | Swagger UI at `/docs` with an Authorize button, ReDoc at `/redoc` | FastAPI |

</details>

## 🚀 Quickstart (Local Development)

Spin up PostgreSQL, Redis, the FastAPI backend and the React client with Docker Compose.

### Prerequisites

```
┌─────────────────────────────────────────────────────┐
│  Required tools                                     │
│  ─────────────────────────────────────────────────  │
│  ✓  Docker  ≥ 24.x   (with Compose plugin)         │
│  ✓  Git                                             │
│  ✓  A Google Gemini API key  (required — the app   │
│     refuses to start without one)                   │
└─────────────────────────────────────────────────────┘
```

### Step-by-step

```bash
# ── Step 1: Clone the repository ─────────────────────────────────
git clone https://github.com/aayush2724/Auralis.git
cd Auralis

# ── Step 2: Configure environment variables ───────────────────────
cp .env.example .env
# Open .env and set at least:
#   GEMINI_API_KEY=your_key_here
#   JWT_SECRET_KEY=a_long_random_secret_at_least_32_chars
#   POSTGRES_PASSWORD=pick_a_password        # docker-compose reads this
#   ADMIN_EMAIL / ADMIN_PASSWORD             # the seeded admin login

# ── Step 3: Start the full stack ─────────────────────────────────
docker compose up --build

# ── Step 4 (optional): seed the knowledge base ───────────────────
# The repo ships four competitor briefs in data/competitors/.
docker compose exec api python -m src.rag.ingest --dir data
# …or upload files from the Knowledge Base tab once logged in.
```

Once the containers are healthy:

Log in with the `ADMIN_EMAIL` / `ADMIN_PASSWORD` you set in `.env`.

`tests/conftest.py` loads `.env` from the repo root and, when `USE_MOCK_LLM` is set, patches the Gemini classifier with a keyword-based stub and replaces Google embeddings with deterministic fake vectors. Without that flag the tests call the real Gemini API.

## ⚠️ Known Limitations

- **A/B split is disabled.** `assign_variant()` returns `ADAPTIVE` for every session; the SHA-256 50/50 split is commented out, so `/ab-test/results` only ever shows one populated variant.
- **"Conversion" means handoff.** The chat route passes `did_convert=should_handoff` to the analytics tracker, so the dashboard's conversion rate is really the share of sessions that were escalated to a human.
- **Confidence is self-reported.** The objection and persona confidence values are numbers Gemini returns alongside its label, not calibrated probabilities. Only the winning label gets a score; the other classes are recorded as 0.
- **The graph runs synchronously.** `run_graph()` blocks the event loop for the duration of the Gemini calls, which limits concurrency on a single worker.
- **CORS is wide open** and there is no rate limiting beyond Gemini's own 429 handling.
